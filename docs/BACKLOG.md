## 待處理

### 1. 重複任務生成搬到資料庫層
- **優先級**：中
- **影響範圍**：桌面版 / 手機版 / Supabase
- **狀態**：暫緩（階段 2 之後再評估）
- **描述**：「完成重複任務 → 自動生成下一筆」的邏輯只存在桌面版本機程式，手機版沒有。若一段時間只用手機，完成的重複任務要等下次開桌面版才會生成下一筆。
- **為什麼留到之後**：搬到 Supabase 是正解（兩端共用一份邏輯），但牽涉資料庫自動化、日期計算重寫、且要同時修一個既有的「防重複比對只看標題」弱點，屬進階任務。
- **動工前要先確認**：
  - 已取得桌面版 generateNextOccurrence / reconcileRecurringTasks 調查報告（已完成）。
  - 「開 App 時滾動過期任務」這塊難純靠資料庫做，可能仍需 App 啟動時呼叫，只能退役桌面端一半邏輯。
  - 切換順序：先把資料庫那套建好、測好，再關掉桌面版生成，避免兩端都生成出現重複。

### 2. 換日時間（dailyResetHour）跨裝置同步
- **優先級**：中
- **影響範圍**：手機版 / 桌面版 / Supabase
- **狀態**：暫緩（先固定為 4）
- **描述**：桌面版換日時間可設定（預設凌晨 4 點），但存在桌面本機 settings.json，沒上 Supabase，手機版讀不到。目前手機版寫死為 4，與桌面預設一致。
- **為什麼留到之後**：要做「自動同步」需在 Supabase 新建設定表，屬獨立項目。階段 0B 先寫死 4 讓兩端當下對齊即可。
- **動工前要先確認**：
  - 在 Supabase 建立 user_preferences 表存 dailyResetHour，桌面與手機都以此為 source of truth。
  - 完成前，暫時不要更動桌面版的 4 點設定，否則兩端會不一致。

### 3. TaskDetail 點完成缺即時回饋（三頁體驗不一致）
- **優先級**：中
- **影響範圍**：手機版
- **狀態**：待實作（CRUD 前後皆可做）
- **描述**：階段 0A 後，TaskDetail 改為「成功才打勾」，慢網路下點擊像沒反應；而 Focus / Tasks 是樂觀更新（點了立刻打勾）。三頁手感不一致。
- **為什麼留到之後**：修法要動到樂觀更新 + loading 動畫，範圍比純文字大，不適合塞進 0A。
- **動工前要先確認**：決定 TaskDetail 改成樂觀更新（與另兩頁一致），或為三頁加上統一的 loading 狀態。

### 4. 失敗提示 toast 抽成共用元件

- **影響範圍**：手機版
- **狀態**：暫緩（維護債）
- **描述**：目前 Focus / Tasks / TaskDetail 各有一份完全相同的 toast inline 程式碼（重複三份）。
- **為什麼留到之後**：不影響使用，屬維護債。可在之後做其他頁面時順手抽成共用元件。

### 5.〔桌面版〕settings.json 混存登入憑證（安全問題）
- **優先級**：高
- **影響範圍**：桌面版
- **狀態**：暫緩（手機版階段 2 完成後回頭處理）
- **描述**：桌面版 settings.json 把登入憑證（JWT token）與一般偏好設定混存在同一個純文字檔，任何能讀到該資料夾的程式都能取得憑證。
- **為什麼留到之後**：這是桌面版的問題、不是手機版，且現在手上多條線同時進行，不宜插隊。但嚴重度高於一般體驗項目，不可被遺忘。
- **動工前要先確認**：把 authSession 從純文字 settings.json 移到 Electron safeStorage / OS keychain。此為桌面版任務，需用桌面版 Code。
